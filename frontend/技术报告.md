# 实验室设备管理系统前端技术报告

## 1. 技术要求

### 1.1 环境搭建

本项目采用 Vue 3 + Vite + TypeScript 构建，使用 Composition API 和 `<script setup lang="ts">` 编写页面组件。

| 项目 | 版本或配置 |
|---|---|
| Node.js | `^22.18.0` 或 `>=24.12.0` |
| Vue | `3.5.x` |
| Vite | `8.x` |
| TypeScript | `6.x` |
| Element Plus | `2.9.x` |
| Axios | `1.8.x` |
| Pinia | `3.x` |
| Vue Router | `4.5.x` |
| ECharts | `5.6.x` |
| 后端地址 | `http://localhost:8080` |
| 前端地址 | `http://localhost:5173` |

安装与启动命令：

```bash
npm install
npm run dev
```

生产构建与类型检查：

```bash
npm run build
```

项目通过 `.env.development` 配置后端地址：

```env
VITE_API_BASE_URL=http://localhost:8080
```

`src/api/http.ts` 创建统一 Axios 实例，设置请求超时时间为 10 秒，并在响应拦截器中处理 401、404、500 和网络错误。接口层严格使用后端真实资源：

```text
/user
/user/login
/category
/lab
/device
```

没有调用分页、统计、Token 或统一响应包装等后端不存在的接口和结构。

### 1.2 组件关系

项目整体采用“应用入口—路由—布局—业务页面—API 服务”的分层结构。

```text
main.ts
 ├── createPinia()
 ├── ElementPlus
 ├── router
 └── App.vue
      └── router-view
           ├── LoginView.vue
           └── MainLayout.vue
                ├── Sidebar / el-menu
                ├── Header / breadcrumb / user dropdown
                └── router-view
                     ├── DashboardView.vue
                     │    └── EChart.vue
                     ├── DeviceListView.vue
                     ├── LabListView.vue
                     ├── CategoryListView.vue
                     └── UserListView.vue
```

主要模块职责如下：

| 模块 | 责任 |
|---|---|
| `src/api/` | 集中封装用户、设备、实验室和分类接口 |
| `src/types/` | 定义 API 数据、表单和实体类型 |
| `src/stores/auth.ts` | 保存当前用户、登录状态和退出登录状态 |
| `src/utils/format.ts` | 日期、金额、数字、状态标签和错误信息格式化 |
| `src/utils/storage.ts` | 将登录用户保存到和恢复自 `localStorage` |
| `src/layout/MainLayout.vue` | 后台整体布局、菜单、面包屑和退出登录 |
| `src/components/EChart.vue` | 统一初始化、更新、resize 和销毁 ECharts |
| `src/views/` | 登录、仪表盘及四类业务管理页面 |

当前前端登录状态只用于页面访问控制。后端没有 JWT、Session 或 Token，因此前端不会伪造认证令牌。

### 1.3 路由设置

Vue Router 使用 `createWebHistory()`，路由设置如下：

| 路径 | 页面 | 权限 |
|---|---|---|
| `/login` | 登录页 | 公开 |
| `/` | 首页仪表盘 | 需要登录 |
| `/devices` | 设备管理 | 需要登录 |
| `/labs` | 实验室管理 | 需要登录 |
| `/categories` | 设备分类 | 需要登录 |
| `/users` | 用户管理 | 需要登录 |

路由守卫逻辑：

1. 未登录用户访问业务页面时跳转到 `/login`。
2. 已登录用户访问 `/login` 时跳转到首页 `/`。
3. 用户退出后清除 Pinia 状态和 `localStorage`，跳转到登录页。
4. 页面刷新时从 `localStorage` 恢复用户信息。

### 1.4 性能分析

#### 网络请求

- Axios 实例统一设置 `timeout: 10000`，避免请求无限等待。
- 业务接口按资源拆分，页面不直接调用 Axios。
- 仪表盘使用现有列表接口获取数据，在前端计算统计值，不增加后端接口。
- 设备管理使用本地过滤，避免向不支持分页和条件查询的后端发送无效参数。

#### 渲染和交互

- ECharts 使用独立的 `EChart.vue` 组件复用。
- 图表更新使用 `setOption`，窗口变化时执行 `resize`。
- 组件销毁时调用 `dispose`，避免图表实例泄漏。
- 表格使用 Element Plus 的 loading 和空数据状态。
- 设备分类、实验室、用户数据通过接口加载后在内存中过滤，适合当前数据规模。

#### 可维护性

- API、类型、状态、格式化工具和页面组件分层。
- 设备、实验室、分类和用户页面使用相同的列表—弹窗—提交—删除交互模式。
- 生产构建可以通过 Vite 进行压缩和资源打包。

当前版本适用于中小规模实验室资产数据。若数据量明显增加，后续应由后端提供分页、条件查询和统计接口，并配合前端动态导入路由进行代码分割。

## 4. 结论

本项目完成了实验室设备管理系统前端的环境搭建、组件组织、路由控制、接口封装、数据格式处理、仪表盘展示和静态构建验证。前端严格按照当前 Spring Boot 后端接口实现，没有假设 JWT、分页、统一响应体或额外统计接口，能够在后端启动且跨域配置正确的情况下通过 `http://localhost:5173` 访问系统。
